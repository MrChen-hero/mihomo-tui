## 1. 目标与范围

把当前「各页能用但视觉与交互标准不一」的 TUI 收敛为**一套可复用的标准化设计系统**，重点四块：

1. **响应式布局与顶栏重构**：建立 mihari 式三档 SizeClass（TooSmall/Compact/Full）响应式系统，顶栏 tab 去掉数字改为纯文本均布，边框与面板严格对齐
2. **顶栏 tab 与状态语义标准化**：选中 tab = accent 加粗（去 `❯` 前缀），右侧状态走语义色分类器，全局状态栏独立底行（对齐 mihari statusbar）
3. **设置页操作区丰富化**：右栏详情面板从「只读展示 + Enter 弹框」升级为**结构化操作区**——当前值首要展示、行内状态徽标（`● 已连接`/` 可更新 ` 实底）、操作行带键帽
4. **其他面板（节点/订阅/日志/连接）统一**：统一 Panel 标题格式（`名称 · 计数 · 状态`）、行焦点符号、表头样式、行末状态徽标、空态文案，全部走同一套 `src/ui/` 组件

**约束（延续既定偏好）：**
- **保持终端绿主题**：`theme.ts` 现有色值不动；仅**新增** `onSolid`（实底徽标前景）一个 token
- **不改整体布局骨架**：标签页结构、双栏/单栏切换、分区划分不动（仅新增响应式降级逻辑）
- **只动展示层**：键位行为、数据流、API 调用、事务逻辑零改动
- **不引入新运行时依赖**：纯自研组件

## 2. 非目标

- 不做左侧全局导航 Rail（5 个页面用顶栏 tab 足够，mihari 的 Rail 是其页面多才需要）
- 不改任一页面的键位集合与交互流程
- 不做 sparkline / ASCII banner（登记为后续，见技术债）
- 不重构 hooks/config/api 层
- 不改设置页的双栏骨架（本期只丰富右栏内容，不动布局）
- 不做独立状态栏组件（Full 布局时状态指标嵌入页脚右侧，Compact 时省略，避免抢占内容高度）

## 3. 响应式布局系统（新增）

### 3.1 SizeClass 三档分级（对齐 mihari）

引入终端尺寸分级系统 `src/ui/layout.ts`，全局共享：

| SizeClass | 宽度范围 | 高度范围 | 顶栏 tab 布局 | 页脚提示 | 状态指标 |
|---|---|---|---|---|---|
| `TooSmall` | < 72 列 | 任意 | 紧凑不换行 | 仅显示调整提示 | 无 |
| `Compact` | 72~99 列 | 任意 | 紧凑单空格间隔 | 精简核心操作 | 无（省略以保证内容高度） |
| `Full` | ≥ 100 列 | 任意 | 均布居中（封顶 16 列/tab） | 完整操作提示 | 嵌入页脚右侧 |

**实现：**
- `classifySize(width: number): SizeClass` 纯函数（可测）
- `useTerminalSize()` hook（Ink 内置 `useStdout()` 包装）返回当前 SizeClass
- 各页面根据 SizeClass 调整布局参数（顶栏 tab 间距、页脚提示长度、状态指标显示）

### 3.2 顶栏响应式布局规则

**Full（≥100 列）：**
```
╭─ mihomo-tui ────────────────────────────────────────────────────────────────╮
│   节点      订阅      日志      连接      设置          规则 · 19090 ● 已连接   │
╰──────────────────────────────────────────────────────────────────────────────╯
 Tab/[] 切换  M 切模式  ESC 退出                v1.19.24 · ↑1.2M/s ↓8.4M/s · 74M
```
- tab 均布居中，每格封顶 16 列，整体居中，左右留 2 列
- 右侧状态段右对齐：`规则 · 19090 ● 已连接`（12~16 列）
- 页脚右侧嵌入状态指标（版本·流速·内存，dim 色，约 36 列）

**Compact（72~99 列）：**
```
╭─ mihomo-tui ────────────────────────────────────────────────────────────╮
│ 节点 订阅 日志 连接 设置                      规则 · 19090 ● 已连接 │
╰──────────────────────────────────────────────────────────────────────────╯
 Tab/[] 切换  ESC 退出
```
- tab 紧凑排布，单空格间隔，左对齐（留 1 列）
- 右侧状态段右对齐
- 页脚精简为核心操作（去掉状态指标、次级操作提示）

**TooSmall（< 72 列）：**
```
╭─ mihomo-tui ─────────────────────────────────────────────────────╮
│ 节点  订阅  日志  连接  设置                   规则 · 19090 ● 已连接│
╰───────────────────────────────────────────────────────────────────╯

          mihomo-tui 需要至少 72 列宽终端
              请调整窗口大小后继续
```
- 顶栏保持不换行（强制挤压）
- 内容区显示降级提示，禁止交互

## 4. 设计系统标准（新增/统一的 `src/ui/` 组件）

### 4.1 语义色扩展（`theme.ts`）

现有 7 个 token 全部保留不动，**新增 1 个**：

| token | 值 | 用途 |
|---|---|---|
| `onSolid` | `ansi256(0)`（黑） | 实底状态徽标（Success/Warning/Danger 背景）上的前景文字，保证 256 色终端对比度 |

新增 `Tone` → 实底背景映射（`toneBg`），供 StatusChip 的实底形态使用（对齐 mihari `RenderStatusChip`）。

### 4.2 状态语义分类器 `classifyTone`（新，纯函数，可测）

对齐 mihari `ClassifyStatusTone`：把状态词（`running`/`已连接`/`检查失败`/`已过期`…）映射到四档 `Tone`。中英混合词表，精确匹配优先、子串兜底。全 app 状态着色的唯一真源——消除现在各页 `switch(status)` 手写色的重复。

**Tone 定义：**
```typescript
export type Tone = 'positive' | 'caution' | 'negative' | 'neutral';
```

**词表示例：**
- `positive`: connected/已连接/running/成功/正常/healthy
- `caution`: reconnecting/重连中/可更新/即将到期/warning
- `negative`: disconnected/断开/失败/错误/已过期/error
- `neutral`: 其他（默认）

### 4.3 `StatusChip` 双形态（`StatusDot.tsx` 扩展）

现有 `StatusChip` 是「`● 文本`」前景着色形态。**新增实底形态** `solid` 属性：

| 形态 | 外观 | 用途 |
|---|---|---|
| `dot`（现状，默认） | `● 已连接`（前景色） | 状态栏、行内轻量状态 |
| `solid`（新） | ` 可更新 `（实底背景 + onSolid 前景） | 设置页操作区的强提示（有更新、需重启）、订阅到期告警 |

实底徽标**必须带文本**（对齐 mihari「status is never color-only」纪律），不做纯色块。

**实底背景色映射：**
```typescript
const toneBg: Record<Tone, string> = {
  positive: ansi256(34),  // 绿底
  caution: ansi256(226),  // 黄底
  negative: ansi256(196), // 红底
  neutral: ansi256(244),  // 灰底
};
```

### 4.4 `Panel` 标题标准格式（约定，不改组件）

统一所有面板标题为 `名称 · 计数 · 状态` 三段式（对齐 mihari `Format*Title`）：

| 页面 | 标题格式 |
|---|---|
| 节点-组栏 | `代理组 · N` |
| 节点-节点栏 | `AUTO · URLTest · 190/228`（名称·类型·可用/总数） |
| 订阅 | `订阅 · N` |
| 日志 | `日志 · info · 缓冲 320/1000`（级别并入标题） |
| 连接 | `连接 · N · ↑1.2M ↓8.4M`（累计流量并入标题） |
| 设置-导航 | `◆ 设置` |
| 设置-详情 | 当前项名（如 `混合端口`） |

### 4.5 顶栏标准（`TopBar.tsx` 重构）

对齐 mihari `RenderControlStrip` + `RenderStatusBar` 的「控制条 + 右侧状态」语言：

**tab 样式：**
- **选中 tab**：`accent 加粗`（去掉 `❯` 前缀，用色彩承载焦点）
- **非选中 tab**：muted

**布局规则（响应式）：**
- `Full`：tab 均布居中（封顶 16 列/tab），右侧状态段右对齐，左右留 2 列
- `Compact`：tab 紧凑排布（两空格间隔），左对齐留 1 列，右侧状态段右对齐
- `TooSmall`：强制挤压不换行，右侧状态段可能被截断

**右侧状态段：**
- 格式：`规则 · 19090 ● 已连接`
- `●` 状态点走 `classifyTone`（连接=positive 绿、重连中=caution 黄、断开=negative 红）
- 状态文本走 `StatusChip` dot 形态

### 4.6 行焦点符号统一（`rowIndicator.ts` 新增）

全 app 统一：
- `▌` = 键盘焦点行（accent 色）
- `❯` = 驻留光标（muted，仅双栏设置页另一栏无焦点时）
- `●` = 业务选中标记（accent 加粗，如节点页已选节点）

**实现：**
- `rowBar(focused: boolean, selected: boolean): string` 返回符号（`▌`/`❯`/`●`/空格）
- `rowBarColor(theme: Theme, focused: boolean): string` 返回 ANSI 色
- 从 `Proxies.tsx` 提升到 `src/ui/rowIndicator.ts`，供节点页/设置页/ListDialog 复用

## 5. 设置页操作区丰富化（重点）

设置页右栏当前是「当前值/说明/取值/影响」4 行纯文本 + `[Enter] 修改`。升级为**结构化操作区**（不改双栏骨架与焦点模型）：

### 5.1 右栏详情面板新结构

```
╭─ 混合端口 ──────────────────────────────────────╮
│  当前值   7890                                   │   ← 当前值加粗/语义色
│                                                  │
│  说明     HTTP/SOCKS 混合代理监听端口             │   ← 斜体 dim
│  取值     1024 – 65535                           │   ← dim
│  影响     写 config.yaml 并重启，活动连接瞬断     │   ← dim
│                                                  │
│  ▌ [Enter] 修改端口                              │   ← 操作行：键帽 + 动作
╰──────────────────────────────────────────────────╯
```

**结构层次：**
1. **当前值**：首行加粗展示（从行内小字提升为首要信息）
2. **状态徽标**（可选，内核区块特有）：`状态` 字段展示 `StatusChip`，如 ` v1.19.30 可更新 `（caution 实底）
3. **说明/取值/影响**：中间区域保持 dim 弱化（不变）
4. **操作行**：底部键帽 + 动作描述（`▌ [Enter] 修改端口`），操作行自身可获得焦点（用 `▌` 标记）

### 5.2 内核区块的状态徽标展示

内核区块特有的**状态徽标行**，使用实底 `StatusChip` 强提示：

```
╭─ 切换版本 ──────────────────────────────────────╮
│  当前值   v1.19.24                               │
│  状态      v1.19.30 可更新                      │   ← caution 实底徽标
│                                                  │
│  说明     下载并切换到指定内核版本，失败自动回滚   │
│  影响     下载 → 校验 → 替换二进制 → 重启服务      │
│                                                  │
│  ▌ [Enter] 选择版本…                             │
╰──────────────────────────────────────────────────╯
```

**状态徽标映射：**
- `v1.19.30 可更新` → caution 实底（黄底黑字）
- `已是最新` → positive dot（绿色前景，轻量）
- `检查失败` → negative dot（红色前景）

### 5.3 操作行交互（保守方案 A）

**本期实现：**
- 右栏操作区**只保留单一主操作行**（`[Enter] 修改端口`）
- 操作行不可独立获得焦点（整个右栏作为一个焦点单元，Enter 触发主操作）
- 信息更丰富（当前值提升、状态徽标）但交互与现状一致，零键位新增

**未来增强（可选，登记技术债）：**
- 内核区块引入**多操作行** + 次级快捷键（如 `[c] 重新检查更新`）
- 操作行间可用 `↑↓` 独立导航
- 需新增键位与页脚提示，测试面更大

### 5.4 右栏面板组件升级

**现有结构：** `panelLines: string[]`（纯文本行数组）  
**升级后：** 保持 `panelLines` 接口不变，内部逻辑调整：

1. **当前值行**：`chalk.bold(currentValue)` + 可选语义色
2. **状态行**（内核区块）：`StatusChip({ text: statusText, tone: classifyTone(statusText), solid: true })`
3. **说明/取值/影响行**：`chalk.dim.italic(text)`
4. **操作行**：`▌ [${chalk.accent('Enter')}] 修改端口`（键帽用 accent）

只读项（如「外部控制」）无操作行，末尾显示 `chalk.dim('只读')`。

## 8. 边界与回归红线

### 8.1 技术约束

- **CJK/emoji 宽度**：`▌`、`●`、实底徽标 padding 一律走 `string-width` 的 `displayWidth`，禁 `slice`
- **实底徽标降级**：不支持背景色的终端 Ink 自动降级为前景色；徽标恒带文本，降级后仍可读
- **色彩降级**：交给 Ink 处理（256 色终端为目标，16 色终端自动映射）
- **窄终端**：`< 72 列` 显示降级提示，禁止交互

### 8.2 回归红线

- **键位零改动**（方案 A）；`useInput` 分支不动
- **全量 `npm test` 通过**（样式/标题断言逐条更新；新增 `classifyTone`/`rowIndicator`/`StatusChip solid` 单测）
- **`npm run typecheck` + `npm run build` 通过**
- **不引入新运行时依赖**（chalk/ink/react 已有，不新增）

### 8.3 验证方式

1. **单元测试**：
   - `classifyTone` 中英词表四档 + 子串兜底
   - `rowIndicator` 三态符号/色
   - `StatusChip solid` 带文本、降级
   - `classifySize` 三档边界值

2. **回归测试**：
   - 全量 `npm test`（标题/样式断言更新）
   - `npm run typecheck`
   - `npm run build`

3. **人工验收**：
   - pty 逐页截屏（110×34 Full 与 80×24 Compact）对照本 spec §3/§5/§6 验收
   - 顶栏 tab 焦点清晰（无数字、accent 加粗）
   - 设置页右栏操作区信息丰富且徽标语义正确
   - 四页标题三段式一致
   - 行焦点符全 app 统一
