## 计划中功能

### v0.3.0 - 订阅增强

**目标**：提升订阅管理的灵活性与可追溯性

- [ ] **批量导入订阅**：从文本文件或剪贴板批量导入多个订阅 URL
- [ ] **订阅分组**：按地域/用途/机场分组展示订阅（如「香港专线」「媒体解锁」「备用线路」）
- [ ] **订阅历史记录**：
  - 记录每次订阅更新的时间戳、节点变化、流量变化
  - 支持查看历史快照与对比
  - 订阅更新失败时可回滚到上一次成功的版本

**设计约束**：
- 历史记录存储在 `~/.config/mihomo-tui/subscription-history/` 下
- 每个订阅保留最近 30 次更新记录（可配置）
- 提供 CLI 命令 `proxy_tui provider history <名称>` 查看历史

### v0.4.0 - 配置管理增强

**目标**：扩展配置能力，覆盖规则、代理链等高级场景

#### 1. 规则管理

TUI 内查看与编辑 `rules` 和 `rule-providers`

**功能点**：
- [ ] 新增「规则」标签页（或在设置页新增子页）
- [ ] 展示当前生效的所有规则（按优先级排序）
- [ ] 支持临时禁用/启用单条规则（运行时）
- [ ] rule-providers 管理：查看、更新、添加、删除
- [ ] 规则测试：输入域名/IP，展示匹配到的规则与出口组

**技术要点**：
- 规则修改走 API `/configs` PATCH，不写 `config.yaml`
- rule-providers 更新走 `PUT /providers/rules/{name}`
- 持久化修改提供「导出到 config.yaml」功能，用户手动确认后才写入

#### 2. 本地节点管理

手动添加 SS/Trojan/VMess/VLESS 等节点

**功能点**：
- [ ] 新增「本地节点」子页面
- [ ] 表单式添加节点：协议选择 → 参数填写 → 实时校验
- [ ] 节点编辑与删除
- [ ] 延迟测试与健康检查
- [ ] 导入/导出节点配置（JSON/YAML）

**技术要点**：
- 本地节点存储在 `~/.config/mihomo-tui/local-proxies.yaml`
- 作为独立 proxy-provider 挂载到 `config.yaml`
- 节点修改后通过 API `/providers/proxies/{name}` 热更新

#### 3. 代理链配置

Relay 组可视化管理

**功能点**：
- [ ] 可视化代理链编辑器（拖拽式或列表式）
- [ ] 测试代理链连通性与延迟
- [ ] 常见场景模板（如「落地中转」「多跳隐私」）

**技术要点**：
- 代理链配置存储在 `config.yaml` 的 `proxy-groups` 中
- 修改后需要 `reload` 配置（非热更新）

### v0.5.0 - 部署与分发优化

**目标**：降低部署门槛，提升跨平台兼容性

#### 单二进制打包

**背景**：当前项目依赖 Node.js ≥22 运行时，对无 Node.js 环境的服务器不够友好。

**方案对比**：

| 方案 | 优势 | 劣势 | 推荐度 |
|------|------|------|--------|
| **Bun** | 支持 `bun build --compile`，可打包为单二进制；兼容 Node.js API | Bun 本身仍在快速迭代，稳定性待验证 | ⭐⭐⭐⭐ |
| **Deno** | `deno compile` 成熟稳定；安全沙箱机制 | 需要适配 Deno 的模块系统（`npm:` specifier） | ⭐⭐⭐⭐ |
| **pkg** | 老牌 Node.js 打包工具 | 已停止维护，不支持 Node.js 22 | ⭐ |
| **nexe** | 打包为单二进制 | 社区活跃度低，兼容性问题多 | ⭐⭐ |

**实施步骤**：
- [ ] 调研 Bun 与 Deno 对 Ink 的兼容性（Ink 依赖 React 与终端 API）
- [ ] 编写打包脚本（`scripts/build-binary.sh`）
- [ ] 在 CI 中自动构建 Linux/macOS/Windows 二进制
- [ ] 更新文档与安装指南

**预期收益**：
- 部署只需下载单个可执行文件
- 启动速度提升（无需加载 Node.js 模块）
- 用户体验对齐 clashtui/vpnkit 等 Rust/Go 项目

## 技术债务

### 高优先级

- [ ] **测试覆盖补充**：
  - Settings 页组件测试覆盖不足
  - 内核版本切换事务流程缺少集成测试
- [ ] **错误处理增强**：
  - WebSocket 断线重连逻辑需要更健壮的指数退避
  - API 调用失败时的用户提示需要更友好（如「内核重启中，请稍候」）
- [ ] **性能优化**：
  - 日志页大量日志渲染时存在卡顿（考虑虚拟滚动）
  - 连接页连接数 >1000 时性能下降

### 中优先级

- [ ] **国际化**：
  - 当前所有文案硬编码为中文
  - 考虑支持英文界面（通过环境变量 `LANG=en_US.UTF-8` 切换）
- [ ] **配置迁移脚本增强**：
  - 支持从 Clash Premium 配置迁移
  - 支持从 sing-box 配置迁移
- [ ] **文档补充**：
  - 常见场景配置示例（如「全局 + 直连白名单」「广告屏蔽规则」）
  - 视频教程或 GIF 演示

### 低优先级

- [ ] **主题定制**：
  - 允许用户自定义配色方案（通过配置文件）
- [ ] **插件系统**：
  - 允许第三方脚本扩展功能（如自定义测速逻辑、节点过滤器）
- [ ] **Web UI**：
  - 提供可选的 Web 界面（保持 TUI 为核心）

## 竞品对比启发

基于 2026-09-22 对 clashtui、potoo0/mihomo-tui、vpnkit 的功能对比分析，本项目的差异化优势在于：

1. **配置安全边界清晰**：唯一写入点 + 事务化操作 + 94%+ 测试覆盖
2. **现代化 TUI 设计**：响应式布局 + 统一设计系统 + 语义色映射
3. **CLI + TUI 双入口**：所有命令支持 `--json`，适合自动化脚本

需要借鉴的功能：
- **clashtui** 的规则管理与代理链配置
- **vpnkit** 的本地节点管理
- **所有竞品** 的单二进制部署体验

## 非目标（Not Goals）

以下功能**不在**项目规划范围内：

1. **内核实现**：不实现代理协议本身，只做管理层
2. **新增监听端口**：不新增 Web Server 或 gRPC 服务（保持轻量）
3. **GUI 桌面应用**：专注 CLI/TUI，桌面需求请使用 Clash Verge / Mihomo Party
4. **配置中心**：不做多设备配置同步（可通过 Git 等工具自行实现）
