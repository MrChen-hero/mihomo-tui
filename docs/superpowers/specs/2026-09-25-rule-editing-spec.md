## 1. 目标与范围

用户已经确认：**先做单条规则的新增、编辑、删除及匹配顺序调整；规则集仍只查看和更新。**

本次交付终端界面中的配置规则编辑器。用户可以连续修改多条规则，检查草稿后一次保存；保存同时更新本地配置和运行中的 mihomo。界面沿用项目现有弹窗样式。

| 纳入范围 | 本次不做 |
| --- | --- |
| 顶层 `rules` 字符串列表的新增、编辑、删除、上下移动 | `rule-providers` 来源、地址、内容的增删改 |
| 常用类型表单、单条原文编辑 | 完整配置文件编辑器、复杂规则可视化表达式编辑器 |
| 草稿、退出确认、校验、备份、写盘、重载与失败恢复 | 自动保存、历史版本管理界面、撤销/重做栈 |
| 引用已有规则集的 `RULE-SET` 单条规则 | `sub-rules` 定义编辑、批量导入导出 |
| 本机同文件系统下的配置管理 | 远程部署、容器路径映射、CLI 写命令 |

TUI（终端交互界面）是本次写操作入口；现有 CLI（命令行接口）的列表、测试、规则集更新行为保持兼容。`RULE-SET` 行只是引用规则集的匹配规则，删除该行不删除规则集。

## 2. 现状、约束与设计取舍

### 2.1 两种规则来源必须分开

- **生效规则**：通过 `GET /rules` 获取，用于现有规则页展示、测试与临时禁用。
- **配置规则**：本地 `config.yaml` 顶层 `rules` 中的原始字符串，是本次持久化编辑的数据来源。
- **草稿**：以一次文件快照为基础的内存副本；保存成功前不改变文件和运行状态。
- **重载（reload）**：让正在运行的内核重新读取配置，不重启系统服务。

`GET /rules` 不保留原始规则全文、所有参数或 YAML 注释，不能用其行号直接修改配置，也不能从 API 响应重建配置文件。编辑器必须独立读取本地文件；从规则页进入时不自动按当前生效规则行号定位文件中的规则。

### 2.2 复用现有能力的边界

- `ConfigManager` 仍是生产 `config.yaml` 的唯一写入入口。
- 不调用 `applyConfig()`：它会运行 `buildSkeleton()` 重生成整份配置，不适合本次只修改 `rules` 的要求。
- 新增接受完整候选 YAML 的规则保存流程，复用配置路径、备份和写入能力；需要补齐异步校验、唯一临时文件和冲突检测。
- 复用 `MihomoClient.reload(absolutePath)`，调用 `PUT /configs?force=false`；不使用只支持通用设置的 `PATCH /configs` 修改规则。
- 沿用 `InputDialog`、`ConfirmDialog`、`ProgressDialog`、`ScrollList` 和现有颜色、边框、FooterLine；不引入新的 UI 框架。
- 编辑规则类型的能力不等于本地匹配器支持该类型。现有保守测试结果不因新增编辑功能而扩大准确性承诺。

### 2.3 为什么采用草稿统一保存

每次删除或移动就重载会造成连续运行状态变化，也难以一次完成有先后关系的调整。统一保存允许用户先完成规则列表，再执行一次校验和应用；代价是需要明确标识未保存状态，以及退出时确认放弃。

## 3. 入口、弹窗与键位

### 3.1 主规则页

| 按键 | 行为 |
| --- | --- |
| `Enter` | 保持现有规则/规则集详情弹窗 |
| `d` | 保持现有临时禁用/启用语义，不变成永久删除 |
| `e` | 打开“配置规则”编辑弹窗，与当前选中的是规则还是规则集无关 |

首次进入读取文件、订阅清单和引用目标，展示加载状态。读取失败展示具体原因及路径，允许返回，不能用 API 数据或空列表替代损坏的本地配置。再次进入重新读取快照，不自动恢复上次放弃的草稿。

### 3.2 配置规则弹窗

居中卡片沿用规则详情弹窗的 accent 标题和边框，常规宽度上限为 64 列，随终端宽度收缩。标题为“配置规则”，有改动时显示“未保存”。卡片内展示文件路径、规则数、当前序号和滚动列表；完整路径与原始规则可在详情中查看。

每行包含：当前全局序号、保护标记、变更标记和规则摘要。新增标 `+`，内容修改标 `*`；移动标记只针对被用户移动的行，不把因插入而顺移的全部行标成移动。保存确认中的“移动 N 条”同样按用户实际移动的不同草稿行计数。

| 编辑器按键 | 行为与边界 |
| --- | --- |
| `↑` / `↓`、`j` / `k` | 移动选中行，不改变匹配顺序 |
| `Enter` | 查看选中配置规则的完整原文、位置、保护原因 |
| `a` | 新增规则，先选择“常用表单”或“单条原文” |
| `e` | 编辑选中规则；能无损映射到表单时默认表单，否则原文 |
| `d` | 弹出删除确认，确认后仅删除草稿行 |
| `J` / `K`（Shift+j / Shift+k） | 将选中规则向后/向前移动一个全局位置 |
| `/` | 设置关键字过滤；匹配规则原文，过滤不改变顺序 |
| `Ctrl+S` | 无改动时提示“没有待保存修改”；有改动时进入保存确认 |
| `ESC` | 无改动直接返回；有改动先确认是否放弃 |

过滤期间允许查看、编辑、删除，**禁用新增和移动**，提示“清除筛选后可新增或调整顺序”；避免用户在看不到相邻规则时插错位置。筛选弹窗提交空字符串即可清除。删除/编辑导致当前行消失时，选择下一可见行，无下一行则选上一行；列表为空时仍可清除筛选或新增。

所有快捷键只在所属弹窗层生效。输入规则原文时 `a/e/d/J/K` 都是文本，不能触发列表操作。子弹窗关闭后恢复列表选择和滚动位置。打开编辑器期间后台刷新不得覆盖草稿。

### 3.3 子弹窗与终端尺寸

- 新增/编辑使用 `InputDialog` 的字段与候选选项机制；`Tab`/上下键切换字段，`Enter` 提交整表，`ESC` 取消本次表单。
- 删除使用 danger 风格 `ConfirmDialog`，显示序号及摘要，`y` 确认、`n/ESC` 取消；普通 `Enter` 不直接删除。
- 保存确认展示新增、修改、删除、移动数量，配置路径及控制器地址；同时提示“重载会重新建立规则状态，临时禁用和本地标记将清除”。
- 不层层堆叠卡片；同一时刻只有当前活动弹窗可接收输入。
- 在 80×24 终端可完成全部操作，列表按可用高度滚动。每个表单最多四个字段；更小尺寸无法容纳时显示“请扩大终端”，保留返回入口，不隐藏确认按钮或截断输入数据。
- 长原文采用单字段横向滚动输入，详情采用可滚动换行显示；仅展示可以截断，实际规则字符串不能截断。

## 4. 新增与编辑规则

### 4.1 常用表单

先用类型选择弹窗选类型，再进入该类型表单。这样无需同时展示类型、值、目标、参数等过多字段。

| 类型 | 表单字段 | 本地检查 |
| --- | --- | --- |
| `DOMAIN`、`DOMAIN-SUFFIX`、`DOMAIN-KEYWORD` | 匹配值、目标 | 值非空，不含换行及逗号；不擅自修改通配符或域名含义 |
| `IP-CIDR`、`IP-CIDR6` | 网段、目标、`no-resolve` 开关 | 有效地址与前缀长度；最终以内核校验为准 |
| `SRC-IP-CIDR` | 源网段、目标 | 有效地址与前缀长度 |
| `SRC-PORT`、`DST-PORT` | 端口或范围、目标 | 单端口或 `start-end`，范围 1–65535，起点不大于终点 |
| `PROCESS-NAME`、`PROCESS-PATH` | 进程名/路径、目标 | 非空，不含换行及逗号；保留大小写 |
| `RULE-SET` | 已有规则集、目标、`no-resolve` 开关 | 名称必须存在于配置 `rule-providers`，参数适用性由内核校验 |
| `MATCH` | 目标 | 不填写匹配值，使用第 5 节的末尾规则约束 |

目标建议来源为当前文件的代理组名、代理名和首版显式支持的内置目标 `DIRECT`、`REJECT`、`REJECT-DROP`、`PASS`。展示顺序固定并去重；不只依赖 `/proxies`，避免混用另一份运行配置的目标。无效或缺失引用不能保存。

表单仅生成自身支持的语法。已有行包含额外参数、复杂端口写法、未知内置目标或无法可靠分离的表达式时，转入原文编辑，不能默默丢参数。表单不提供类型切换；需要改类型时通过编辑方式选择切到原文，或删除后新增。

### 4.2 单条原文模式

支持新增和编辑完整的单条规则字符串，例如复杂逻辑规则或当前表单未覆盖的 `GEOSITE`、`DOMAIN-REGEX`。不实现一套完整的 mihomo 语法解析器。

- 原文必须为单个非空字符串，不允许换行、NUL 或粘贴多条规则；不要求用户输入 YAML 列表的 `-` 或外层引号。
- 可以 trim 整行两端的空白，但不得改写内部空白、括号、参数和大小写。
- 只识别规则类型前缀和可靠支持的简单格式。复杂规则不能通用地 `split(',')` 后再拼接。
- 原文提交表示加入草稿，不表示内核已认可。统一保存时执行完整候选配置的 `mihomo -t`，失败则保留草稿并给出错误。
- 已存在但表单不支持的规则原样保留，可查看、原文编辑、删除和排序；不因 UI 不认识就过滤掉。
- 支持原文 `SUB-RULE` 引用，但不编辑 `sub-rules` 定义，引用有效性由完整配置校验确认。

## 5. 顺序、兜底与自动维护规则

### 5.1 普通规则顺序

界面提示“通常按从上到下顺序匹配；PASS 等特殊动作按内核语义继续处理”。序号表示实际配置位置，不表示固定身份。

- 默认在选中行之前插入；选中受保护前缀时插在前缀之后。空列表插到首位，没有选中行则插在末尾 `MATCH` 之前或列表末尾。
- 表单新增 `MATCH` 始终放到末尾。
- `J/K` 每次移动一位，保持选中对象不变；边界处不循环，显示不可继续移动的原因。
- 允许重复规则，不按内容去重；两个内容相同的规则是两个独立草稿对象。

### 5.2 MATCH 政策

- 保存时最多一条顶层 `MATCH`，且如果存在必须是最后一条；此约束是产品防误操作规则，不宣称是内核的唯一合法语法。
- 不强制配置必须有 `MATCH`，也不自动补一条。删除唯一 `MATCH` 时确认框补充“将移除显式兜底规则”，保存确认再次显示“无显式 MATCH”；具体后续行为由内核决定。
- 已有多条或不在末尾的 `MATCH` 仍加载并标出问题，允许用户删除多余项、移动至末尾修复；问题未修复不能保存。
- 正常情况下不能把普通规则移到末尾 `MATCH` 后，也不能把有效末尾 `MATCH` 向上移。已有位置错误的 `MATCH` 允许向下移动以修复。
- 原文新增或修改形成 `MATCH` 时同样校验，不绕过约束；原文模式不会偷偷重排，存在位置错误时明确提示并让用户移动。

### 5.3 订阅直连规则保护

`subscriptionDirectRules()` 根据订阅主机名生成 `DOMAIN,<host>,DIRECT`，`buildSkeleton()` 会把它们放到规则前部。允许用户删除后又自动生成，会造成持久化语义不一致。

- 编辑器读取当前订阅清单，调用同一生成函数得到应受保护的规则内容。
- 以生成的规范字符串做内容匹配，并且只接受确定等价的简单三段格式（允许分隔符旁空白）；不尝试推断复杂表达式是否等价。
- 匹配到的每一行显示“订阅直连 · 自动维护”，禁止编辑、删除和移动。人工创建的同内容规则也会被保护，界面明确“按规则内容识别”，不声称有来源 ID。
- 新增或编辑普通规则时，若结果等价于已维护的保护规则，拒绝该次草稿提交并提示“此订阅直连规则已由程序维护”，避免本次保存后产生下一次无法编辑的重复保护项。
- 正常受保护规则构成列表前缀，普通规则不能移动到它们之前。
- 若清单要求的规则缺失、重复或没有形成与生成结果一致的有序前缀，允许查看，但禁用本轮写操作并说明需要先通过订阅配置流程同步；本编辑器不悄悄修复或补全系统规则。
- 订阅清单读取失败不能当作“没有订阅”，必须阻止写操作。保存前同时检查清单快照，变化则要求重新打开编辑器。
- 若无配置管理清单且项目加载逻辑将其定义为合法空清单，沿用该语义；不能自行把损坏文件视为此情形。

## 6. 草稿模型与 YAML 保留

### 6.1 会话数据

| 对象 | 必要字段/职责 |
| --- | --- |
| 文件快照 | 绝对路径、原始 UTF-8 字节、内容摘要、订阅清单摘要、文件权限信息 |
| YAML 文档 | `YAML.parseDocument` 的节点树、解析错误、原有 `rules` 节点 |
| 草稿行 | 会话稳定 `id`、原始位置、原始节点、当前原文、保护原因、变更状态 |
| 草稿会话 | 当前行顺序、已删除行 ID、选择与过滤状态、是否存在实际变化 |
| 保存结果 | 当前失败阶段、备份路径、磁盘状态、内核状态、可恢复操作 |

内容摘要使用 SHA-256（内容指纹，用于判断文件是否变化）。会话 ID 不写入 YAML，也不使用运行时规则 index。`dirty` 以最终规则内容和顺序是否偏离快照判定；改后再改回、移动后移回不留下虚假的未保存状态。

### 6.2 文档修改要求

- 使用 `YAML.parseDocument` 并检查解析错误；只替换、插入、删除或移动 `rules` 序列内对应节点。
- 无 `rules` 键时可从空草稿开始，保存时新增该键；已有 `rules` 必须是字符串序列，`null`、映射、混合非字符串列表均拒绝编辑。
- 未改行复用原节点；编辑行继承节点注释；移动时节点及其附属注释一起移动。删除确认说明该行附属注释也会删除，序列级注释保留。
- 非 `rules` 字段的值与注释应保留，包括未知字段。序列化可能改变排版、引号或换行，因此**不承诺成功保存时整文件字节不变**。
- 对 `rules` 本身或其条目涉及的 YAML 锚点、别名、合并来源及无法可靠保留的自定义标签，首版拒绝写操作并说明原因；不把复杂节点静默展开成普通字符串。
- 无关字段中的合法锚点/别名保持原节点；修改后的文档仍须完整解析和内核校验。
- 校验阶段不落盘；失败回滚恢复保存前的原始字节和权限，而不是重新序列化旧对象。

## 7. 保存与生效流程

### 7.1 写操作前提

首版只支持本机、同文件系统、项目管理的配置文件。编辑器展示本地绝对路径和连接的控制器地址；非回环地址仅允许查看，不开放写操作。对回环地址，首次保存确认还需明确“该控制器属于本机读取此配置路径的 mihomo”，该会话记住确认。

回环地址不能证明内核身份；SSH 隧道、容器端口转发不在首版支持范围。`GET /configs` 也不能证明原始配置路径。通过显式传入路径和内核安全路径检查降低误重载风险，不宣称已自动发现内核启动路径。

本地管理路径必须是普通文件，首版不替换符号链接。找不到 mihomo 二进制、不可读写、控制器不可访问或保护状态无法确定时，禁用保存并给出原因。

### 7.2 状态与执行顺序

保存过程分为 `editing → confirming → validating → writing → reloading → verifying`，失败后进入 `editing` 或 `recovery-required`；重复按保存不能产生第二个事务。事务指一次完整保存和必要的失败恢复，不意味着磁盘和内核之间具有数据库式原子性。

1. **准备**：捕获本次草稿，检查保护规则、MATCH、引用和文档结构，生成完整候选 YAML；保存确认期间不允许继续修改其内容。
2. **冲突预检**：重新读取配置及订阅清单，与进入编辑器时的快照比较。不同则保留草稿并提示冲突，不覆盖、不自动合并；用户可继续查看草稿，或确认丢弃并重新加载。
3. **候选校验**：按第 8 节在隔离目录异步运行内核校验，显示进度；失败返回草稿。
4. **备份和最终检查**：重新检查两份摘要，通过 `ConfigManager` 创建唯一且不覆盖旧备份的文件；核实备份与原快照一致。检查失败立即停止。备份失败禁止写入。
5. **原子写入**：在配置同目录创建独占的唯一临时文件，设置原权限、写入候选并关闭后 rename 到目标。沿用现有文件归属要求，无法保持必要属性时提前拒绝；不使用共享的固定 `.tmp` 文件。
6. **写后复验**：读取磁盘，确认字节摘要等于候选，并在隔离校验上下文中复验实际写入内容；随后再核查配置与清单未变化。失败按第 9 节恢复，不继续重载。
7. **明确路径重载**：调用 `reload(configPath)`，不得传空路径，不执行 `systemctl restart`。应用前后的界面都明确这是整份配置重载，内核自行决定对存量连接的影响。
8. **回读确认**：获取完整 `/rules`，按下一节核查可观察字段；确认期间再读磁盘摘要。如果磁盘已变化，进入外部变更状态，不宣称保存完成。
9. **收尾**：更新草稿基线并清除已确认的未保存状态，刷新主规则页和规则集信息，清除旧临时禁用展示、本地标记、旧测试结果及基于旧序号的选中状态；保留备份并按项目七天策略清理。

备份命名继续兼容 `config.yaml.bak.*` 清理前缀，增加毫秒/随机后缀并使用独占创建，避免同一秒保存覆盖。临时文件仅清理本事务创建的文件。

### 7.3 成功与未确认的边界

- `PUT /configs` 返回成功表示内核接受重载；它不证明所有远程规则集已经下载完成，也不证明所有规则的实际匹配结果。
- 对可可靠映射的简单规则，比较 `/rules` 返回的顺序、类型、匹配值和目标；实现需使用真实内核测试确认映射，不比较 UI 筛选后的数量。
- 对复杂规则或 API 缺失的 flag，仅以完整候选内核校验、明确路径重载成功和运行规则读取成功为依据，界面不宣称“所有参数逐项核对成功”。
- 简单规则出现确定的顺序或内容不一致，视为应用核查失败，按第 9 节处理；不能只用“条数一样”判定成功。
- 回读最多进行三次，每次使用客户端请求超时，两次间隔 500 毫秒；持续不一致才进入恢复，持续请求失败则进入下述未确认状态。不得无限等待或把请求失败当成空规则列表。
- 重载成功但 `/rules` 暂时不可读：显示“配置已保存，重载已接受，运行规则读取未确认”，保留候选为磁盘基线，提供重新读取操作；**不因一次读取失败回滚或重复重载**。未确认解除前禁止下一次保存，避免状态叠加。

## 8. 校验环境与中断

现有 `validate()` 使用同步 `execFileSync`，最多阻塞 120 秒，不可直接放入交互保存路径。新增异步校验能力，沿用 120 秒上限并限制捕获输出长度；不移除规则、不开“跳过内核校验”的后门。

- 校验使用独立临时目录，候选配置本身保持完整；绝不对生产配置目录执行可能写缓存的 `mihomo -t`。
- 从当前 mihomo 数据目录复制可定位的已有 geodata 和本地 provider 依赖至隔离目录，保留相对目录关系。实现针对项目生成配置及本次支持资源类型列出显式依赖收集规则，不做通用文件系统镜像。
- 校验副本中的资源路径若需指向隔离副本，仅改校验副本，不改最终候选规则或持久化路径；两者差异须限制为已列明的资源路径映射。
- 首版支持数据目录下可复制的相对资源路径；外部绝对路径、逃逸数据目录的路径、无法隔离的依赖或缺少所需 geodata 时，阻止保存并说明具体资源问题。provider 懒加载不等于远程内容已验证，需在结果中保留这一边界。
- 不主动更新生产规则集缓存。若内核校验自身尝试联网，只可能写隔离目录，超时作为校验失败返回，不无限重试、不以联网成功作为必需前提。
- 写前校验允许取消：终止并回收子进程，清理临时目录，返回原草稿。写入开始后直至重载或恢复结束不开放取消。
- 当前 `App` 的 Ctrl+C 早于 `keysCaptured()` 处理，实施必须增加与本事务绑定的退出保护；确认/校验前可走放弃确认，关键写入阶段提示“正在保存，请等待完成”。不能仅依赖弹窗捕获按键。
- 不承诺能拦截 `SIGKILL`、断电或操作系统强制终止，也不在本次引入持久化事务日志。异常退出可能留下磁盘与内核不同步状态，可利用备份恢复；临时文件不能被下次启动当作有效配置。

## 9. 失败恢复与并发边界

采用进程内单事务门闩阻止规则编辑器重复提交；保存期间捕获界面按键，阻止跳转设置、订阅等本进程其他写入口。不为本次改造全项目跨进程写锁。

内容摘要检查不能构成与任意外部编辑器之间的原子比较交换：检查与 rename 之间仍有很短的竞争窗口。界面和文档应提醒不要同时由其他程序编辑同一配置；本次不承诺多进程严格串行。

| 失败位置/情况 | 文件与内核处理 | 用户可见结果 |
| --- | --- | --- |
| 读取、结构检查、写前校验、备份失败 | 不写正式配置，不重载 | 返回草稿，保留输入并指出阶段 |
| 写前发现文件或清单变化 | 不覆盖、不重载 | “配置已被其他操作修改”，提供重新加载前的放弃确认 |
| rename 前写临时文件失败 | 清理本事务临时文件，正式文件应不变 | “写入失败”，附安全处理后的错误 |
| 写后复验失败，尚未重载 | 确认磁盘仍为候选后，通过唯一临时文件原子恢复备份 | 明确“文件已恢复，未执行重载” |
| 重载拒绝、连接断开、超时，或确定的回读内容不一致 | 网络超时不能假定未生效；确认磁盘仍为候选后恢复备份，并向同一控制器重载同一绝对路径一次 | 按恢复结果分别说明磁盘和内核状态，禁止无界重试 |
| 重载成功，运行规则读取失败 | 保留候选文件，仅重试读取 | “已保存，运行状态待确认”，不报告普通成功 |
| 写入后发现外部修改 | 不用备份覆盖新文件，不继续自动重载 | “检测到外部修改，已停止自动恢复”，显示备份路径 |
| 恢复文件失败或恢复后重载失败 | 保留备份及诊断信息，停止后续保存 | “恢复未完成”，分别显示磁盘状态、内核状态及已知/未知项 |

回滚前不仅检查候选摘要，也检查订阅清单和控制器上下文未变化；无法确认则停止自动恢复。恢复之后再次读取文件和运行规则，回读失败仍只能称“恢复重载已接受，运行状态未确认”。

写后成功恢复原快照时，保留用户草稿以便修正后重试。进入 `recovery-required` 或发现外部新文件时，禁止直接重试旧事务，需用户处理状态并重新加载基线。

错误信息包含阶段、配置/备份路径和可操作原因；不得打印完整配置、控制器密钥、订阅 URL token。内核输出可能包含配置片段，必须脱敏后截断展示。

## 11. 验证与验收标准

### 11.1 针对性测试矩阵

| 场景 | 必须验证的结果 |
| --- | --- |
| 新增、编辑、删除、移动连续进行 | 保存前文件/API 无写入；保存一次只执行一个重载流程 |
| 相同内容的两条规则 | 可分别编辑/删除，移动后选中身份不变，不按内容去重 |
| 表单与原文 | 正确生成简单规则；复杂表达式/未知 flag 原样保留；换行/空行拒绝 |
| 目标与规则集引用 | 不存在的引用不能保存；删除 RULE-SET 行不删除规则集定义 |
| MATCH | 唯一且末尾；允许无 MATCH 并警告；已有异常允许修复，不静默排序 |
| 自动维护规则 | 禁止增删改位置；异常前缀与清单读取失败阻止写入 |
| 过滤与列表边界 | 禁止过滤中新增/移动；删除最后可见行后选择有效；边界不循环 |
| YAML 保留 | 非规则字段语义及注释保留，移动带注释，不支持节点明确拒绝 |
| 无效完整配置/缺资源/校验超时 | 写前失败保留草稿与原文件，子进程和隔离目录可清理 |
| 同秒备份/重复保存 | 备份互不覆盖，唯一临时文件不冲突，重复提交被拒绝 |
| 外部修改 | 在校验中、写后及恢复前注入变化，确认不会主动覆盖已检测的新文件 |
| 写入失败/重载失败/网络结果不确定 | 检验各阶段操作顺序、原字节恢复、备份保留和内核状态文案 |
| 读取未确认与恢复失败 | 不伪报成功，不重复重载，不继续提交旧快照 |
| 按键与退出 | 输入字符不触发父层；ESC 放弃确认；写入阶段 Ctrl+C 不直接退出 |
| 回归 | 原 Enter 详情、d 临时禁用、本地测试、规则集更新与 CLI 读操作保持兼容 |

### 11.2 验证执行

实施时按三个检查批次验证，不为文档变更运行业务测试：

1. **针对性自动测试**：运行新增草稿/事务测试及受影响的规则视图、配置管理、退出行为测试；使用临时目录、假控制器、可注入校验器测试失败顺序，不接触生产配置。
2. **项目构建**：执行 `npm run build`（当前为 `tsc -p tsconfig.json`），确保类型检查和编译通过，不重复执行等价类型检查。
3. **隔离真实内核验收**：使用 mihomo v1.19.24、临时配置目录与独立控制端口，完成新增→编辑→移动→删除→重载回读，记录规则顺序和文件变化；验证无效配置被阻断及至少一个重载失败恢复案例。用最小确定性规则校验，不依赖用户真实订阅或网络资源。

人工终端验收覆盖 80×24、长规则、空列表、弹窗切换和保存期间退出操作。自动测试不能替代实际可见布局检查；验证结果需如实记录。

**完成标准**：用户能在统一风格弹窗中完成四类操作；草稿取消不落盘；一次保存后文件和内核状态有明确证据；失败不会被误报为成功；恢复边界、临时禁用重置和不支持资源有明确提示。
